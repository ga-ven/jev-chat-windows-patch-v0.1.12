# JevChat-Windows v0.1.12 增强补丁：客服角色 + 自动巡场 + 需求台账

给 [JevChat-Windows](https://github.com/jev-chat/jev-chat-windows) **v0.1.12** 的 exe 加这几样：

1. **判断模型自定义来源** —— 「判断 · Jev」除了 OpenRouter / TypeSafe 直连，还能自己填 Base URL 和密钥
2. **自动发送** —— 填入微信输入框后自动按 Enter 发出去；更进一步有「全自动回复」，候选一出来就自己填、自己发
3. **真 @ 对方** —— 群聊回复时输入 `@` 从弹窗里选中人，对方能收到真正的 @ 提醒（不是干巴巴一段文字）
4. **分条发送** —— 一条回复拆成 2~3 条发，中间停一两秒，像真人一句一句说
5. **客服角色** —— 一段自定义角色提示词，按系统级身份注入（不是塞进「说话风格」凑数）。
   内置一份「荔致教育客服」模板：问全六项需求 → 复述确认 → 答家长疑惑 → 引导登记/试课
6. **自动切换会话** —— 每 10 秒扫一次会话列表，点开**行尾有未读红点**的那个，交给原来那条链读消息、生成、发送
7. **家长需求台账** —— 开着客服角色时，每次回复完顺手把对话抽成结构化需求，写进 CSV（按会话名去重更新）

顺带修掉了上游在**浅色主题 + 高 DPI** 下把会话名截成半截的 bug（见下文）。

> 只适用于官方 **v0.1.12** 的 `jev-chat-windows.exe`
> （sha256 `4f0b79c63cbfbb283edcac71c32c07c038089127cb7c2926c9d6a3126119fec8`，18,632,863 字节）。
> 脚本会核对，对不上就不动手。

## ⚠️ 先读这段

**自动发送是上游明确拒绝做的功能。** 上游的
[Issue #1](https://github.com/jev-chat/jev-chat-windows/issues/1) 就是「建议增加个自动回复功能」，
作者按 `not planned` 关闭，原话：

> 这条不会做，是项目的硬边界，不是优先级问题。**发送永远由人来按。**
> 程序只做到「把候选填进输入框」，不发回车、不点发送按钮，代码里也没有任何发送路径。
> 理由：① 这是个回复辅助，不是聊天机器人，最后一眼必须是人看的；
> ② 自动发送就变成了替用户在微信里说话的自动化行为，这已经触碰微信的使用规则。

这份补丁**违背了上游这个设计原则**。风险自己担：

- 微信的发送键必须设成「Enter 发送」。设成 Ctrl+Enter 的话，自动发送只会换行，消息发不出去
- 输入框里如果还留着你打了一半的草稿，会连同本次粘贴一起被发出去
- 发出去的消息收不回来
- 持续自动回复（尤其群聊）的行为特征很像机器人，理论上存在被判定异常的风险
- **「自动切换会话」+「全自动回复」一起开就是无人值守挂机**：程序会自己找人、自己说话。
  拿自己的号跑客服话术，封号风险比手动点「填入」高得多，建议先用小号跑通再说

默认全部关闭，开了才会生效。

## 用法

1. 下载本仓库（Code → Download ZIP）解压。
2. 双击 `安装补丁.bat`。
   - 脚本按 sha256 找官方 v0.1.12 的 `jev-chat-windows.exe`：桌面快捷方式、下载、文档目录都翻一遍。
   - 找不到就把 exe（或它所在的文件夹）拖到 `安装补丁.bat` 上。
   - 程序开着也没关系，脚本会先关掉它；原 exe 备份成 `jev-chat-windows.exe.bak`。
3. 打开程序 → **设置 → 回复偏好**，两个开关按需打开：

| 开关 | 行为 |
| --- | --- |
| **填入后自动发送** | 你点「填入」→ 粘进输入框后自动按 Enter 发出。仍需你点一下 |
| **全自动回复** | 候选一出来就自己填、自己发，连「填入」都不用点。留 0.8 秒缓冲，期间关开关或切会话就不发 |
| **分条发送** | 一条回复拆 2~3 条发，中间随机停 1.8~3.2 秒。**只在自动发送开着时生效**，否则几条会全堆在输入框里一起发出去 |
| **回复时真 @ 对方** | 关着：回复前面加「@名字」文字，对方收不到通知。开着：输入 `@` 再从微信弹窗里选中人，对方会收到真的 @ 提醒 |
| **自动切换会话** | 每 10 秒扫一次会话列表，点开最上面那个有未读红点的会话。默认跳过群聊和系统会话 |
| **自动切换时也处理群聊** | 群名带「(6)」这种人数后缀的也自动切换并自动发。**默认关**，群多的时候别开 |

还有一块 **客服角色设定** 多行输入框（同页），填了就按客服身份说话，空着就是原来「模仿我平时说话」的样子。

### 关于真 @

实现方式是往输入框里逐字打 `@名字`，微信会弹成员列表并按输入内容实时过滤，然后按一次回车选中列表第一项：

```python
type_text("@" + at_target)   # 微信弹窗 + 过滤
keybd_event(0x0D)            # 回车 = 选中第一项
```

选不中的话，输入框里就留着 `@名字` 这段纯文本，正文接上去等于退化成文本 @，不会更糟。

但**群里有重名、或者目标名字是别人名字的前缀时，可能选中错的人**。第一次开建议先在小群或小号上试。

### 关于分条

先按 `。！？` 切，切不开再按逗号和空格切；不足 8 字的碎片并回前一段；最多 3 条；原本就不足 12 字的短消息（比如「好的」）不拆。

拆句用的是本地规则，没有额外调模型 —— 多一次请求会多 2~5 秒延迟、费用翻倍，而拆句这种活儿规则已经够用。觉得断句不自然可以提 issue。

### 关于客服角色

角色提示词是按**系统级身份**注入的，不是拼在「说话风格」后面凑数。命中角色时做三件事：

- 覆盖掉系统提示词里「你就是 me 本人，不是客服、不是助手」那条规则
- 跳过「我平时是这么说话的」样本 —— 否则你平时的聊天习惯会把客服腔冲掉
- 温度从 `1.2` 降到 `0.85`，客服口径要稳，不能一句一个说法

模板里除了身份，还写清了流程和红线（不报价、不报老师名单、不承诺提分、拿不准就说「确认一下回您」）。
输入框清空保存，就完全回到原来「像本人在说话」的行为。

### 关于自动切换

- 只认会话行尾的**红色未读徽标**（`#FA5151` 那一族像素），没有红点不会乱点会话；灰色免打扰小铃铛不算未读
- 点的是会话行中间偏右的位置：避开头像和昵称，也不压到徽标本体
- 节奏：有未读 → 点开 → 冷却 **7 秒**（开了全自动）/ **25 秒**（只生成候选，留时间给你自己看）
- 微信团队、文件传输助手、腾讯新闻、公众号这些**系统会话点开看一眼但绝不自动发**
- 群聊默认跳过；要连群一起处理，得单独开「自动切换时也处理群聊」
- 会把微信窗口抬到前台才能点，你在用电脑时会觉得窗口在跳

### 关于需求台账

- 文件在程序目录：`家教需求台账.csv`，UTF-8 带 BOM，Excel 双击不乱码
- 只有「客服角色」非空时才抽；抽取是附加动作，失败不影响回复
- 列：`更新时间 / 家长·会话 / 地点 / 年级科目 / 学生 / 上课时间 / 课酬 / 老师要求 / 备注`
- 按会话名去重：新抽到的非空字段覆盖旧的，空字段**不会**把已经填好的内容抹掉
- 设置页底部有「打开需求台账」按钮，首次回复之后才会生成文件

4. 判断来源（可选）：设置 → 模型 → 判断 · Jev → 来源选「自定义 · OpenAI 兼容」→ 填 Base URL
   （一般带 `/v1`）→ 填密钥（换来源要重填一次，留空会继续用上一把）→ 点「获取模型」挑一个 → 保存。

还原：双击 `卸载补丁.bat`，它会从 `.bak` 拷回来。`检查补丁.bat` 只看状态不改文件。
只想退掉自动发送、保留自定义来源？在设置里把开关关掉就行，不用换文件。

## 补了什么

补丁模块从 5 个扩到 **10 个**，`src/` 下按上游路径原样放着：

| 文件 | 改动 |
| --- | --- |
| `core/providers.py` | `JEV_PROVIDERS` 多 `custom_openai`、`custom_typesafe`；`JEV_CUSTOM` 跟着扩 |
| `core/jev_client.py` | 两种自定义来源的判断和取模型；两条手写 HTTP 合成一个 `_post_json` |
| `core/draft.py` | 新增 `role` 参数与 `ROLE_SYSTEM`：角色模式下换系统提示词、跳过模仿样本、温度降到 0.85 |
| `core/engine.py` | `analyze()` 多 `jev_base_url`、`role`；新增 `extract_lead()` 把对话抽成结构化需求（一轮 JSON 调用，失败返回 `{}`） |
| `app/settings.py` | 存/读 `jev_base_url`、`auto_send`、`auto_fill`、`multi_send`、`real_at`，以及 `role_prompt`、`auto_switch`、`switch_groups`、`ledger_path` |
| `app/overlay.py` | Base URL 行、六个开关、客服角色输入框 + 「填入荔致教育示例」、台账按钮、底部文案联动、全自动触发逻辑 |
| `app/fill.py` | `fill()` 加 `auto_send` 和 `at_target`（真 @）；剪贴板写不进去时降级逐字输入；点击坐标兜底；抽出 `foreground()` / `click_at()` 供自动切换用 |
| `app/capture.py` | `find_chat_hwnd` 跳过「窗口在但抓不到画面」的僵尸窗口；抽出 `grab()`；新增 `unread_rows()` 按红色徽标定位有未读的会话行 |
| `app/worker.py` | 会话列表宽度按 DPI 折算（`LIST_W_100 × dpi / 96`），并且只有 `chat_area()` 认不出边界时才跳 |
| `app/ocr.py` | `who_said` 加位置兜底（右边缘靠左的不可能是自己发的） |
| `main.py` | 传参；填入前重新找窗口；触发条件改成「这批里有对方的话就分析」；分条拆句与逐条发送；新增 `drive_switch()` 自动巡场、`save_lead()` 台账 upsert、`is_group` / `may_auto_send` 放行规则 |

## 途中修掉的上游 bug（微信 4.2 下才暴露）

这些不是新功能，是上游在微信 4.2 上本来就不工作的地方：

**1. 消息区把左侧会话列表也 OCR 进去了**

暗色主题下会话列表和聊天区底色完全一样（都是 `[30,30,31]`），`chat_area()` 分不开，
`x0` 退化成整个窗口左边缘（8）。于是「腾讯新闻」「文件传输助手」「微信团队」这些**列表条目
被当成对方说的话**，连锁导致：会话名显示 `?`、生成的回复像在描述人而不是回话、
把用户自己的消息当成对方（「自己接话」）。修法是标题和消息区都跳过左侧会话列表 ——
跳多少见下面第 6 条，不能写死 300px。

**2. 窗口句柄会被复用**

微信重建窗口后，旧句柄会落到一个 **160×28 的托盘小窗**上（坐标 `-32000,-32000`）。
拿它算点击坐标是负数 → 点到屏幕外；但 `fill()` 不抛异常，界面照样显示「✓ 已尝试填入」，
**看着成功实际啥也没干**。修法：每次填之前重新找窗口，并校验 area 是否还合理。

**3. 多开时挑中「僵尸窗口」**

同时开多个微信实例时，没在用的那些 `IsWindowVisible` 仍是 True、窗口矩形也正常，
但 `PrintWindow` 抓出来是一张只有 2 种颜色的白板（DWM 没在画它）。
判据不能用像素方差（白板只有边框那点深色也能把方差撑到 22+），得用**主导颜色占比**。

**4. 剪贴板被别的程序长期占用**

`OpenClipboard` 连续失败时原来直接报错。现在降级为 `SendInput` + `KEYEVENTF_UNICODE`
逐字输入，绕开输入法和剪贴板，中文也能进。

**5. 全自动会被群聊打断**

候选生成后要等缓冲区，群聊一条接一条，缓冲期内来新消息会把候选标记成「已失效」，
全自动于是主动放弃。改成只要候选内容还在、会话没切就照发。

**6. 高 DPI + 浅色主题下会话名只剩半截**

`worker.py` 里调了 `SetProcessDPIAware()`，抓到的画面是**物理像素**；但跳过会话列表的偏移写死成 `300`（按 100% 缩放估的）。而 `x0` 的含义会随主题变：

- **暗色**：列表和聊天区同色（`[30,30,31]`），`chat_area()` 分不开，`x0` 退化成窗口左边缘（≈8）。这时 +300 正好等于「跳过列表」
- **浅色**：两者底色不同（列表 `238,238,240` / 聊天区 `250,250,250`），`chat_area()` **已经正确给出 537**，再无条件 +300 就变成 837

175% 缩放下实测：窗口宽 1564px，图标栏 0~116，列表 116~536，聊天区 537 起。
从 837 开始裁，「事业编+公务员+名校生+爸爸 (6)」只剩「爸爸 (6)」，而 `read_title()` 取的是
「同一行最左边的文字」——于是会话名认成半截，消息区左边那段（头像、对方气泡开头）也被切掉，
表现就是「识别错乱」。

改法两条：列表宽度按 DPI 等比放大（`306 × dpi / 96`，175% 得 536，与实测吻合）；
**只有 `x0` 退化成窗口左边缘时才跳**，`chat_area()` 认出边界就直接用，不再叠加。
三种缩放都验算过：100% → 307/306、125% → 384/382、175% → 537/536（浅色/暗色）。

## 和上游那个补丁仓库的关系

「判断模型自定义来源」的功能来自
[XiaoRui114514/jev-chat-windows-custom-jev](https://github.com/XiaoRui114514/jev-chat-windows-custom-jev)，
那个仓库的补丁**只做 v0.1.11**（写死了 v0.1.11 的 sha256），直接套到 v0.1.12 上会被拒绝。

也不能硬绕过去 —— v0.1.11 → v0.1.12 之间上游大改了 `app/overlay.py`（+225 −137）、
`main.py`、`app/settings.py`。补丁原理是整块替换模块字节码，直接覆盖会把 v0.1.12 新增的
`app/i18n.py`（界面语言 / 韩语）、`app/chatapps.py`、`app/ocr_windows.py` 架空。

所以这里**没有复制上游的补丁包**，而是把净改动**移植到 v0.1.12 的真实源码上**再重新编译。
自动发送那部分是本仓库自己写的。

## 两条自定义来源的区别

| 来源 | 接什么 | Base URL |
| --- | --- | --- |
| **自定义 · OpenAI 兼容** | 任意 chat/completions 接口 | 一般要带 `/v1` |
| **自定义 · TypeSafe 兼容** | TypeSafe 协议的镜像 | **只到域名，别带 `/v1`**（SDK 自己拼 `/v1/systemone`） |

OpenAI 兼容那条是把 7 道判断题打包成一轮 `chat/completions` 发过去，用你自己的模型答。
**判断质量取决于那个模型读不读得懂这套题目**，不是真 Jev。想要真 Jev，选 OpenRouter、
TypeSafe 直连，或用 TypeSafe 兼容那条。

## 验证过什么

- **全量字节码校验**：补丁后 exe 的 PYZ 解出来，5434 个模块全部能 `marshal.loads`，
  与原版数量一致；TOC 逐项比对，除补丁的 10 个外其余零差异。
- **拼接自检**：用本仓库 `patch/` 里的 6 个载荷按 `apply.ps1` 的逻辑重新拼一遍原版 exe，
  得到的大小 `18,770,676` 和 sha256 `8c65c2d6…` 与 manifest 完全一致；从源码重跑
  `tools/build_patch.py` 得到的 6 个载荷哈希与仓库里的二进制载完全一致（可复现）。
- **实跑**：Windows 11 + 微信 4.2.0.13（`Weixin.exe`）+ 175% 缩放 + 浅色主题实测 —— 群名完整、
  消息读出正确；点「填入」能把文字送进微信输入框（未开启自动发送时不发出）。
- **角色话术**：真实接口（`agnes-3.0-flash`）跑出来是「罗湖鸿翔花园这边能安排，孩子现在基础大概
  什么水平呀」「那麻烦您发下大概预算范围…对老师性别有要求吗」，不是「像本人闲聊」。
- **需求抽取**：真实接口 5.6 秒，把「罗湖鸿翔花园、高一化学、女孩、一周一次周六、340 一次、
  女老师节奏紧凑」抽成六个字段，与手写的需求单逐项对得上。
- **未读检测**：合成 3 个 `#FA5151` 徽标全部命中（中心误差 0），灰色免打扰小铃铛不误判，空帧返回空列表。
- **台账**：同一会话第二次只补了课酬和备注 —— 其余字段保留、空的没把已有内容抹掉，BOM 正常。
- **回归过的场景**：暗色主题、多开微信、窗口最小化后恢复、剪贴板被占用、无未读时不乱点。

## 限制

- **只认官方 v0.1.12 的 exe**（sha256 `4f0b79c6…`），脚本会核对，对不上就不动手。
  换版本要拿 `tools/build_patch.py` 重新生成一份。
- **程序更新到新版本后补丁就没了**（更新会覆盖 exe），重新打一遍就行；
  注意更新可能把 `.bak` 一起顶掉，重要的话先另存一份原版 exe。
- 自动切换只认**行尾的红色未读徽标**。如果你关了消息预览、用了第三方皮肤，或者徽标被主题改色，
  可能识别不到 —— 表现是「不切换」，不会误点别的会话。
- 自动切换靠**前台点击**，非整数缩放（如 137%、225%）下坐标可能有偏差。
  拿不准就开「调试视图」，它会画出程序实际框选的范围。
- 客服角色模式是拿「像本人」换「像客服」：清了输入框保存就回到原样。
- 需求抽取每次回复多一轮模型调用（多 3~6 秒、多一份费用），只在客服角色非空时才跑。
- 台账按**会话名**去重：同一个家长改了备注名会变成两行，得手动合。
- 两条界面文案改成了「三家给的是同一个 Jev，必填。」和
  「看上面选的来源：OpenRouter、TypeSafe 直连，或你自己的服务。」
  i18n 韩语表里还是按老文案存的 key，所以切韩语时这两条显示中文。功能不受影响。
- 群聊里如果有人只发表情包或图片，OCR 读不到内容，不会触发回复。

## 重新构建

需要 **Python 3.11**（exe 里是 3.11 字节码，别的版本编译出来塞不进去）：

```bash
python tools/build_patch.py --exe <官方 exe 路径> --out patch --patched-exe out/jev-chat-windows.exe --app-version v0.1.12
```

`tools/build_patch.py` 基于上游补丁作者的脚本，这里加了 `--app-version` 参数，
并把 `MODULES` 扩到 10 个（`app/capture.py`、`app/worker.py`、`app/ocr.py`、`app/fill.py`、
`core/draft.py` 都进去了）。构建是确定性的：同一份源码 + 同一个原版 exe，跑出来的载荷逐字节一致。
